# Media Stack

`jelly-01` (`192.168.60.131`, VMID `131`) runs the complete internal media
stack. Terraform gives it 4 vCPU, 16 GiB RAM, a 50 GiB OS disk and a 1 TiB
`datav1` disk. Ansible formats the blank second disk as ext4 and mounts it at
`/data`.

## Services And Network Isolation

| Service | Address | Network path |
|---------|---------|--------------|
| Jellyfin | `http://jellyfin.lab` | Traefik to `jelly-01:8096` |
| Seerr | `http://seerr.lab` | Traefik to `jelly-01:5055` |
| Sonarr | `http://sonarr.lab:8989` | LAN only, direct |
| Radarr | `http://radarr.lab:7878` | LAN only, direct |
| Prowlarr | `http://prowlarr.lab:9696` | LAN only, direct |
| FlareSolverr | internal Compose network only | Prowlarr proxy for protected indexers |
| Bazarr | `http://bazarr.lab:6767` | LAN only, direct |
| qBittorrent | `http://qbittorrent.lab:8080` | LAN only, through Gluetun |

Only qBittorrent uses `network_mode: service:gluetun`. Its process is also
bound to Gluetun's `tun0` interface. Gluetun's firewall is the primary kill
switch and qBittorrent cannot fall back to the VM's normal default route.
Sonarr, Radarr, Prowlarr, Bazarr, Jellyfin and Seerr use the ordinary `media`
Docker bridge and retain normal connectivity if the VPN is unavailable.

No qBittorrent peer port or Web UI route is exposed by Traefik. Mullvad removed
port forwarding, so qBittorrent works as an outbound-only peer behind the VPN.

## Storage And Hardlinks

All download and library consumers see exactly the same `/data` paths:

```text
/data
├── torrents
│   ├── movies
│   └── tv
└── media
    ├── movies
    └── tv
```

qBittorrent, Sonarr, Radarr and Bazarr mount `/data:/data`. Jellyfin mounts only
`/data/media:/data/media:ro`. Both trees live on the same ext4 filesystem, and
the role enables `copyUsingHardlinks` in Sonarr and Radarr. Do not replace the
single `/data` mount with separate Docker volumes or filesystems; that breaks
hardlink imports.

Application databases and settings live under `/opt/media-stack/config` on the
OS disk. Both data and configuration therefore survive container recreation.

## Secrets

Edit the existing encrypted production vault:

```bash
cd ansible
ansible-vault edit inventories/prod/group_vars/all/vault.yml
```

Add these values:

```yaml
vault_media_mullvad_wireguard_private_key: "<Mullvad WireGuard private key>"
vault_media_mullvad_wireguard_addresses: "<Mullvad tunnel address, for example 10.x.x.x/32>"
vault_media_qbittorrent_admin_password: "<long unique password>"
vault_media_jellyfin_admin_password: "<long unique password>"
```

The role refuses to run if any value is missing. It renders Mullvad credentials
only to `/opt/media-stack/.env` (`root:root`, mode `0600`) and verification
credentials to a separate root-only file. Neither file is committed. Servarr
API keys are generated by their applications and read locally by Ansible with
`no_log`; they do not need to be added to the vault.

The default Mullvad exit country is Poland. Override
`media_mullvad_server_countries` or `media_mullvad_server_cities` in inventory
variables if another exit is required.

## Deployment

Review the Terraform plan carefully because adding a 1 TiB disk consumes
`datav1` capacity:

```bash
make plan
make apply
make inventory
make ping
make bootstrap
make media
make dns
make proxy
make apps
```

`make site` is the equivalent full desired-state deployment. Use
`make media-update` to pull configured image tags and recreate this stack.

The role performs first-run configuration automatically:

- qBittorrent categories `tv` and `movies` point to their matching torrent
  directories;
- Sonarr and Radarr use qBittorrent and import to the matching media root;
- Prowlarr full-syncs indexers to Sonarr and Radarr;
- FlareSolverr is registered in Prowlarr as an indexer proxy with the
  `flaresolverr` tag;
- Bazarr connects to Sonarr and Radarr;
- Bazarr applies the `polen` Polish/English language profile to existing and
  newly added movies and series, then searches for missing subtitles;
- SubDL is enabled for Polish and English subtitles, with YIFY Subtitles as an
  additional account-free movie provider; SubDL credentials remain in Bazarr's
  persistent configuration and are never stored in the repository;
- Jellyfin creates read-only Movies and TV libraries;
- Jellyfin monitors both libraries in real time so completed imports appear
  without waiting for the periodic full scan;
- Seerr connects to Jellyfin, Sonarr and Radarr.

Recyclarr is intentionally not enabled. Its quality profiles and custom format
scores are opinionated and can overwrite an existing Servarr policy. Add it to
this role only after selecting and reviewing a TRaSH Guides profile.

### Cloudflare-protected indexers

FlareSolverr is not exposed on a host port. Prowlarr reaches it at
`http://flaresolverr:8191/` over the private Compose network. When adding an
indexer that explicitly requires FlareSolverr, assign the `flaresolverr` tag to
that indexer. Leave the tag off ordinary indexers so their traffic does not pay
the browser-proxy overhead.

FlareSolverr can solve many browser challenges but cannot guarantee access to
sites that require interactive CAPTCHA completion. Use only indexers you are
authorized to access.

## Verification

Run the automated runtime checks after deployment:

```bash
make media-verify
```

The check verifies container health, Mullvad exit ownership, the VPN kill
switch, independent non-VPN connectivity, qBittorrent categories, Prowlarr and
Bazarr connections, hardlink settings, a real same-inode filesystem probe,
Jellyfin libraries and recovery after restarting the whole Compose project.
The test briefly stops Gluetun and qBittorrent, then restores both.

After the first real download, confirm that Sonarr or Radarr imported it as a
hardlink by comparing device and inode values for the two paths:

```bash
stat -c '%d:%i %n' /data/torrents/movies/<file> /data/media/movies/<movie>/<file>
```

Both `%d:%i` values must match. This final check uses a real application import;
the automated probe validates the underlying filesystem and configured hardlink
policy without downloading third-party content.

To validate VM boot recovery, reboot only after the normal check succeeds:

```bash
ssh homelab@192.168.60.131 sudo reboot
# Wait for SSH to return, then:
make media-verify
```

## Intel Quick Sync

The role safely auto-detects `/dev/dri/renderD128` inside the VM. If it exists,
it passes `/dev/dri` and the guest `render`/`video` group IDs into Jellyfin,
enables QSV with HEVC decoding, and verifies the Intel media driver. It does not
change the Proxmox host or enable passthrough.

The current `pve` host uses an Intel HD 630 at `0000:00:02.0`. It is isolated in
IOMMU group 0. Generic PCIe attachment on `q35` does not boot this guest. The
working configuration uses Proxmox legacy IGD mode with the existing i440fx/BIOS
guest:

```bash
pvesh create /cluster/mapping/pci \
  --id jellyfin-igpu \
  --map node=pve,id=8086:5912,subsystem-id=1028:07a1,path=0000:00:02.0,iommugroup=0
qm stop 131
qm set 131 --vga none
qm set 131 --hostpci0 mapping=jellyfin-igpu,legacy-igd=1,rombar=1
qm start 131
```

Verify `/dev/dri/renderD128` in the guest, then run `make media`. The installed
version of the BPG Terraform provider does not expose Proxmox's `legacy-igd`
flag, so that flag and `vga: none` remain explicitly documented host-side
exceptions. The reusable VM module ignores host-side `hostpci` drift so a normal
Terraform apply cannot strip the unsupported flag. Review every `make plan` and
never approve removal of `legacy-igd=1` or `vga: none` for VM 131. No permanent
i915 blacklist or host reboot is required: Proxmox dynamically binds the device
to VFIO while the VM is running.

If Proxmox itself uses the iGPU, the device is not isolated, or remote recovery
is unavailable, leave passthrough disabled. Software transcoding remains the
safe fallback.
